## 3. 最新不可更改的产品决策

- 初始登录使用“账号编号 `accountCode` + 初始密码”，不使用姓名登录。
- Admin 导入新用户时只需要姓名；不要求输入身份或组别。
- 所有导入的新账号默认 `LEARNER`。
- Admin 可在后台把普通账号改为 `SENIOR` 或 `ADMIN`，必须服务端授权并审计。
- 无 OIDC 时，本地账号模式可以永久独立运行。
- 初始密码默认不自动过期；修改、重置、归档或进入 `OIDC_ONLY` 后失效。

## 4. 目标架构

### 4.1 身份与会话

- `User` 是唯一正式业务用户；作品、角色、组别和匿名 ID 均关联 `User.id`。
- `LocalCredential` 独立保存本地 `scrypt` 密码哈希。
- `OidcIdentity` 保存未来的 `(issuer, subject)` 绑定；邮箱补录使用 `accountCode` 匹配，禁止按姓名自动合并。
- `Session` 是可撤销服务端会话；学生和 Admin 不再使用两套身份体系。
- `User.role=ADMIN` 是后台唯一授权依据；移除共享 `ADMIN_PASSWORD` 认证。
- 认证模式：`LOCAL_ONLY -> HYBRID -> OIDC_ONLY`；OIDC 不是强制终点。

### 4.2 正式领域

- `Event` / `EventSettings`
- `User` / `Group`
- `Submission` / `Day1Slot` / `Day3Bottle`
- `Asset`
- `EventAnonymousId`
- `ArtworkPublicId`
- `AdminAuditLog`

旧 `Person`、`Image`、`SystemSetting` 仅作迁移兼容。不得继续向 `Person` 增加正式字段。

### 4.3 图片

- 保留客户端压缩和浏览器直传 R2；图片不得经 Vercel Serverless 中转。
- `DATABASE_URL` 只用于运行时 pooled 查询，`DIRECT_URL` 只用于 migration。
- R2 key 必须由服务端签发并原样持久化，不从 URL 反推。
- 正式 `Asset` 记录处理状态；公开内容只能使用处理完成的安全衍生图。
- 本地 `LOCAL_UPLOAD_DIR` 仅用于开发，不可用于生产持久化。

### 4.4 权限

- 所有权限在服务端执行。
- Learner 与 Senior 共用 `authoringEnabled`。
- 写入还需要对应 Day 开放，并遵守 `allowEditing`。
- Browse 没有 Admin 全局开关；Viewer 必须先提交自己的对应 Section。
- 匿名和仅身份模式必须在查询/序列化阶段删掉不可见字段，不能只在前端隐藏。
- 普通作品入口统一 `/artworks/{publicId}`；Public ID 不是访问凭据。
