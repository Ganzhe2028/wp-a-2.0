## 1. 架构与数据流

应用部署在 Vercel。Next.js Route Handler 负责鉴权、业务校验和数据库记录；Neon PostgreSQL 是业务数据的唯一来源；Cloudflare R2 只保存二进制图片。

```text
浏览器
  ├─ 登录 / 管理操作 / 保存数据 ─────→ Next.js API ─────→ Neon PostgreSQL
  └─ 图片压缩 → 申请预签名 URL ──────→ Next.js API ─────→ R2 签名
                         └─ PUT 图片 ────────────────→ Cloudflare R2
                                                    ↓
                              POST 图片 key + public URL → Next.js API → Neon Image 记录
```

关键原则：图片不能经 Vercel 中转；数据库保存图片 `key` 和公开 `url`，不能只保存 URL 或由 URL 反推出 key。

## 2. 环境变量与运行边界

| 变量 | 用途 | 要求 |
|---|---|---|
| `DATABASE_URL` | Neon pooled 连接串，应用查询使用 | 所有运行时 Prisma 查询只用它 |
| `DIRECT_URL` | Neon direct 连接串 | 仅 Prisma migration 使用，不能进入应用代码 |
| `R2_ACCOUNT_ID` | R2 endpoint 账号 ID | 与下列 R2 凭据配套 |
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | R2 S3 API 凭据 | 生产仅在 Vercel 环境变量中保存 |
| `R2_BUCKET` | 图片桶名 | 当前约定为 `owek-images` |
| `R2_PUBLIC_BASE_URL` | R2 图片公开域名 | 不带末尾 `/` 也能使用；生成 URL 时会规整 |
| `ADMIN_PASSWORD` | 管理员登录密码，同时为管理员 JWT 签名密钥 | 缺失即失败，使用足够长的随机字符串 |
| `SESSION_SECRET` | 学生 JWT 签名密钥 | 至少 32 字节；建议 `openssl rand -base64 48` 生成 |
| `APP_BASE_URL` | CSV 导出、QR 码中的应用根地址 | 生产为 `https://msoweek.site` |
| `LOCAL_UPLOAD_DIR` | 仅本地开发的图片磁盘目录 | 设置后绕过 R2，绝不能作为生产持久化方案 |

`.env.local` 由 Next.js 自动读取；Prisma CLI 默认读取 `.env`。本地迁移使用：

```bash
DOTENV_CONFIG_PATH=.env.local npx prisma migrate deploy
```

本地构建前需把 `.env.local` 导入当前 shell：

```bash
set -a; source .env.local; set +a; npm run build
```

生产从 `main` 自动部署到 Vercel。`dotenv` 必须保留在 `dependencies`，因为构建中的 `prisma.config.ts` 会加载它。

## 3. 数据库与 Prisma

### 3.1 连接方式

- Prisma schema 位于 `prisma/schema.prisma`，迁移位于 `prisma/migrations/`。
- `prisma.config.ts` 保存 `DATABASE_URL` 与 migration 专用的 `DIRECT_URL`。
- Prisma 使用 `engineType = "client"` 和 Neon driver adapter，不依赖 Rust query engine 二进制。
- `lib/prisma.ts` 是唯一的 Prisma Client 入口，开发环境挂到 `globalThis`，避免热重载和 serverless 冷启动耗尽连接。
- 本地 URL 指向 `localhost` 或 `127.0.0.1` 时使用 `@prisma/adapter-pg`；其他 URL 使用 `@prisma/adapter-neon`。
- `app/generated/prisma/` 是已提交的生成产物。改 schema 后必须生成客户端并一并提交。

禁止用 `prisma db push` 覆盖已有生产库；结构变更必须新建并提交 migration。先用 `migrate status` 确认数据库状态，再执行 `migrate deploy`。

### 3.2 数据模型

| 模型 | 作用 | 关键约束 / 说明 |
|---|---|---|
| `Person` | 学生与运营账号、作品、活动状态 | `code`、`editToken`、`username` 全局唯一；`passwordHash` 可空以兼容历史数据；`role` 默认为 `LEARNER` |
| `Image` | DAY 1 的 14 张图库图片 | 归属 `Person`；保存 R2 `key`、公开 `url`、排序值 `sort`、`hidden` |
| `LocationCard` | 历史位置页遗留表 | 导入时仍会创建一条，以保持 `code` 结构完整；当前没有 `/loc` 页面和编辑 UI |
| `Favorite` | 历史收藏遗留表 | 数据库保留，当前没有读写 API 或 UI；不得恢复“谁收藏了我”的反查功能 |
| `SystemSetting` | 活动总开关 | `key` 为主键，`value` 为字符串；只能保存非敏感开关值 |

`Person` 的业务字段：

| 字段 | 当前含义 |
|---|---|
| `id` | 内部主键；R2 图片路径第一段必须等于它 |
| `code` | 6 位 URL-safe 短码，共享给 `/u/{code}`、`/nfc/{code}`、`/package/{code}` |
| `editToken` | 24 位历史遗留 token，DB 非空且唯一；导入必须继续生成，页面编辑已不使用 |
| `username` / `passwordHash` | 学生登录账号及 scrypt hash |
| `role` / `groupName` | `LEARNER`、`SENIOR` 或 `ADMIN` 及分组，用于目录排序与显示 |
| `avatarUrl` | DAY 1 头像的公开 URL；必须是当前用户自己上传的 R2 key |
| `images` | DAY 1 图库；仅 `hidden=false` 的记录计入上限和展示 |
| `day1SubmittedAt` | DAY 1 提交时间；非空表示 DAY 1 内容已发布并触发对应互解锁 |
| `day3Answers` | JSON，两个 section、各 32 项的 0–5 数值；读取时会规范化非法值 |
| `day3SubmittedAt` | DAY 3 提交时间；非空表示 DAY 3 内容已发布并触发对应互解锁 |
| `published` | 兼容性字段；DAY 1 提交时写入 `true`，当前展示权限不依赖它 |
| `hidden` | 管理侧人工下架标记；`/u/{code}` 显示“该页面已隐藏”而非空白 |

关联删除由数据库执行：删除 `Person` 会级联删除 `Image`、`LocationCard` 和 `Favorite` 记录。**这不会删除 R2 对象**，详见第 5 节的存储清理事项。

## 4. 账号、会话与权限

### 4.1 两套独立会话

| 身份 | Cookie | JWT 内容 | 时长 | 签名密钥 | 认证入口 |
|---|---|---|---|---|---|
| 学生 | `owk_session` | `pid`（Person ID）、`role: student` | 14 天 | `SESSION_SECRET` | `POST /api/auth/login` |
| 管理员 | `owk_admin` | `role: admin` | 8 小时 | `ADMIN_PASSWORD` | `POST /api/admin/login` |

两个 cookie 均为 `httpOnly`、`SameSite=Lax`、`Path=/`，生产环境增加 `Secure`；只能由 API 通过 `Set-Cookie` 下发，不能改为 `document.cookie` 或 localStorage。学生会话使用服务端 cookie，是为了避免 Safari ITP 对脚本写入存储的短周期限制。

`ADMIN_PASSWORD` 与 `SESSION_SECRET` 通过懒读取函数取得；缺失或空值会抛错并拒绝认证，禁止增加默认密钥。管理员密码现在同时被用作管理员 JWT 签名密钥，因此它应是长随机值并仅限管理员掌握。

### 4.2 登录和密码

- 学生账户通过 admin 批量导入创建；未指定用户名时 `username = code`。
- 密码为 12 位、可打印的随机字符串，存储格式为 `salt_hex:hash_hex`，用 Node 内置 `crypto.scryptSync` 生成 64-byte hash；比较使用 `timingSafeEqual`。
- 明文密码仅在导入成功响应及重置密码响应中返回一次，数据库、导出 CSV 和人员列表均不返回它。
- 学生不提供自助找回密码；管理员通过 `POST /api/admin/reset-password` 重置。
- 学生登录按 IP（15 分钟 20 次）及用户名（15 分钟 5 次）限制；管理员登录按 IP（15 分钟 10 次）限制。

限流实现位于 `lib/rate-limit.ts`，是单实例内存 Map。Vercel 多实例、重启或扩缩容时限流状态不会共享，也不会持久化；它是基础防护，不可当作分布式攻击防护。如未来需要更强限制，应引入集中式限流存储并保留现有错误语义（429）。

### 4.3 当前访问规则

- `/home`、`/day1`、`/day3`、`/browse`、`/u/{code}` 需要学生会话；无会话时页面回到 `/?next=...`。
- `/nfc/{code}` 与 `/package/{code}` 公开；NFC 页始终匿名且不提供跨用户入口。
- 查看他人 Day N：浏览者自己的 `dayNSubmittedAt` 必须非空；对方尚未提交时返回“无内容”状态，而不是权限错误。
- `hidden=true` 时 `/u/{code}` 返回下架占位状态。
- admin API 全部先验证 `owk_admin`，学生 session 不能替代管理员身份。

## 5. 图片上传与 Cloudflare R2

### 5.1 正常上传流程

1. 客户端用 `browser-image-compression` 压缩：最长边不超过 1600px，目标不超过 500KB，输出 WebP。
2. 客户端调用 `POST /api/upload-url`，提交 `{ contentType, purpose }`；允许 `image/jpeg`、`image/png`、`image/webp`。
3. 服务端验证学生 session、DAY 1 只读状态、上传限流和图片数量，生成 key：`{personId}/{nanoid}.{ext}`，返回 `{ putUrl, publicUrl, key }`。
4. 浏览器直接对 `putUrl` 发 PUT 到 R2。R2 CORS 必须允许生产域名的 `PUT` 与 `GET`，并允许 `Content-Type` header。
5. 客户端把服务端返回的同一组 `{ url: publicUrl, key }` 提交给 `POST /api/me/images`；服务端在数据库保存 `Image`。
6. 头像复用 1–4 步，但通过 `PATCH /api/me` 写入 `avatarUrl`；头像不进入 `Image` 表，也不占 14 张图库上限。

R2 key 必须由 `/api/upload-url` 返回并原样传递。服务端保存前会同时检查：key 以 `{session.personId}/` 开头，且 URL 精确等于 `getPublicUrl(key)`。`PATCH /api/me` 对头像采用同一归属校验，不能仅按公开域名前缀放行。

### 5.2 图片数量、并发与编辑状态

- DAY 1 必须为 1 个头像 + 14 张图库，`submitDay1` 才会成功。
- `/api/upload-url` 在发签名前检查图库数量；`purpose: "avatar"` 不计入此限制。
- `/api/me/images` 在 `Serializable` transaction 内再次计数，并最多在 Prisma `P2034` 序列化冲突时重试 3 次；这是最终防止并发上传超过 14 张的保护。
- 每位学生申请上传 URL 的限制为 10 分钟 20 次。
- DAY 1 一旦提交，`allowEdit` 不为 `true` 时，申请 URL、保存图片、删除图片全部返回 409；打开 `allowEdit` 后可再次编辑。重复 `submitDay1` 仍返回 409。
- 删除图片会先删除 R2 对象，再删除数据库记录。若 R2 删除失败，数据库记录会保留，避免出现指向不存在对象的记录。

### 5.3 本地开发模式

设置 `LOCAL_UPLOAD_DIR` 后，签名 URL 与公开 URL 都改为 `/api/local-upload?key=...`。该 route：

- PUT 仍验证 session、key 归属、MIME 类型；单文件上限 2MB；
- GET 公开读取文件并设置一年 immutable cache；
- 使用的 key 有严格正则，防止目录穿越。

这只适合本地调试。Vercel 文件系统不是持久盘，生产不得设置该变量。

### 5.4 存储运维注意事项

- R2 公共域名意味着已保存的图片 URL 可被直接访问；当前产品不把图片当私密对象。若要改为私有图片，必须整体改为签名读取方案，不能只关闭 Public Access。
- 上传到 R2 与写 `Image` 表不是一个原子事务：上传成功但保存记录失败时会留下孤儿对象。客户端保留“上传失败、图片留在本机、可重试”的状态；运营可按 `personId/` 前缀定期审计孤儿对象。
- admin 删除 `Person` 依赖数据库 cascade，不会自动调用 R2 删除；删除账号前应按该 `personId/` 前缀清理 R2 对象，或后续补一条受控的异步清理流程。
- 生产 CORS 当前操作手册给出 `AllowedOrigins: ["*"]` 以方便现场使用。若域名稳定，建议收紧为 `https://msoweek.site` 和必要的预览域名；变更前须验证 presigned PUT。

## 6. 活动提交与系统设置

### 6.1 提交 API

`GET /api/me/submissions` 返回当前学生的 Day 1 / Day 3 提交时间及经过规范化的 Day 3 草稿。

`PATCH /api/me/submissions` 的 body：

| `action` | 条件 | 写入结果 |
|---|---|---|
| `submitDay1` | `day1Open=true`、未提交、已有头像且图库非隐藏图片不少于 14 | 写 `day1SubmittedAt` 和 `published=true` |
| `saveDay3` | `day3Open=true`；若已提交则须 `allowEdit=true` | 写入规范化后的 `day3Answers` |
| `submitDay3` | `day3Open=true`、未提交 | 写 `day3Answers` 与 `day3SubmittedAt` |

Day 3 提交允许未完成的项目；`parseDay3Answers` 将数据规范为 2 × 32 个 0–5 整数，缺失或非法数值归零。已提交的 Day 3 在 `allowEdit=true` 时仅可 `saveDay3`，不能再次 `submitDay3`。

### 6.2 SystemSetting 六个有效开关

| key | 含义 | 缺失记录时的默认值 |
|---|---|---|
| `day1Open` | 未提交学生可进入 / 提交 DAY 1 | `true` |
| `day3Open` | 未提交学生可进入 / 提交 DAY 3 | `true` |
| `allowEdit` | 已提交作品是否可重新编辑 | `false` |
| `showNames` | 全站是否显示真实姓名 | `false` |
| `profileComplete` | `/u`、`/nfc` 是否展示图片与小瓶子明细 | `true` |
| `navEnabled` | 是否开放 Browse 与跨页导航 | `true` |

默认值来自每个 `settingEnabled()` 调用点，不是数据库默认值。管理员接口可以写任意 key，但应用只消费上表六项；不要将密钥、密码或个人敏感资料写入 `SystemSetting`，因为 `/api/settings?key=` 可公开读取任意指定 key。

## 7. 后端 API 速查

### 学生与图片

| 方法 | 路径 | 鉴权 | 主要输入 / 输出 |
|---|---|---|---|
| POST | `/api/auth/login` | 无 | `{ username, password }`；成功设置 `owk_session` |
| POST | `/api/auth/logout` | 学生 cookie | 清除学生 cookie |
| GET | `/api/me` | 学生 cookie | 返回本人资料和图片 |
| PATCH | `/api/me` | 学生 cookie | 更新姓名、年级、bio、`avatarUrl`；文本有长度限制，头像必须归属本人 |
| POST | `/api/upload-url` | 学生 cookie | `{ contentType, purpose? }` → `{ putUrl, publicUrl, key }` |
| POST | `/api/me/images` | 学生 cookie | `{ url, key }` → 新建图片记录 |
| DELETE | `/api/me/images?id={imageId}` | 学生 cookie | 删除本人图片的 R2 对象和数据库记录 |
| GET | `/api/me/submissions` | 学生 cookie | Day 1 / Day 3 状态和草稿 |
| PATCH | `/api/me/submissions` | 学生 cookie | `submitDay1`、`saveDay3`、`submitDay3` |
| PUT / GET | `/api/local-upload?key=` | 本地模式 | 本地开发的上传 / 图片读取 |

### 管理员

| 方法 | 路径 | 主要用途 |
|---|---|---|
| POST | `/api/admin/login` | 校验口令并设置 `owk_admin` |
| POST | `/api/admin/logout` | 清除管理员 cookie |
| GET | `/api/admin/session` | 返回当前 admin 会话是否有效 |
| POST | `/api/admin/import` | 批量事务导入账号，响应一次性含明文密码 |
| GET | `/api/admin/export` | 导出 `chineseName,englishName,username,code,homepage` CSV，不含密码 |
| GET / PATCH / DELETE | `/api/admin/persons` | 查列表、改姓名/角色/组别、永久删除账号 |
| POST | `/api/admin/reset-password` | 按 `code` 生成并返回一次性新密码 |
| GET / PATCH | `/api/admin/settings` | 读取 / 更新活动开关 |
| GET | `/api/admin/qr/print` | 生成所有 `/u/{code}` 的批量 QR 打印页 |
| GET | `/api/settings?key=` | 公开读取单个非敏感系统设置 |

### 批量导入约定

`POST /api/admin/import` 接收 `rows`。每行至少有 `chineseName`，还可包含 `englishName`、`grade`、`username`、`role`、`groupName`。`role` 只接受 `SENIOR` 或 `ADMIN`，其余值归为 `LEARNER`。

导入会预先检查本批与数据库中的用户名重复；随后在一个 Prisma transaction 内同时创建 Person 与对应 LocationCard，任一步失败即整批回滚。导入生成的 `code`、`editToken` 都会查询现有数据以避免冲突。HTTP 409 表示唯一性冲突，不能把它当作部分成功处理。

## 8. 运维、验证与故障定位

### 8.1 建议验证清单

```bash
DOTENV_CONFIG_PATH=.env.local npx prisma migrate status
npx tsc --noEmit
npm run lint
set -a; source .env.local; set +a; npm run build
npm run audit:harness
```

核心人工验收：导入一名测试用户并记录一次性密码；学生登录；上传头像和 14 张图片；提交 DAY 1；验证他人 DAY 1 互解锁；保存和提交 DAY 3；重置密码；删除一张图片并确认 R2 对象消失；确认管理员 cookie 与学生 cookie 互不影响。

### 8.2 常见问题

| 现象 | 优先检查 |
|---|---|
| Prisma 迁移/构建报缺 `DATABASE_URL` | 是否使用 `.env.local`；Prisma 命令是否带 `DOTENV_CONFIG_PATH`；构建是否已 source 环境变量 |
| Vercel 构建失败或 Prisma 运行异常 | `dotenv` 是否仍在 dependencies；`DATABASE_URL` 是否为 pooled URL；不要设置旧的 `PRISMA_QUERY_ENGINE_LIBRARY` |
| 学生总被登出 | `SESSION_SECRET` 是否一致且非空；cookie 是否从 API Set-Cookie 下发；是否在微信内置浏览器与 Safari 间切换 |
| 上传 PUT 失败 | R2 CORS 的 origin、PUT、Content-Type；R2 API 凭据、bucket、公开域名；浏览器传的 content type 是否在白名单 |
| 保存图片返回 409 | 图库已达 14 张，或 DAY 1 已提交且 `allowEdit` 关闭 |
| 头像 PATCH 返回 400 | 必须使用当前 session 通过 upload-url 返回的 URL/key；不能复用他人 URL 或手写 R2 URL |
| 导入后无法找回旧密码 | 这是预期安全设计；hash 不可还原，直接重置并重新发放密码 |
| 删除账号后 R2 仍有文件 | 这是当前已知非自动清理项；按该 Person ID 前缀手工清理或补受控清理任务 |

## 9. 变更红线

- 不要把图片上传改为经过 Next.js / Vercel 的服务端中转。
- 不要从 `publicUrl` 猜 key，也不要放宽 key 所有权和 URL 相等校验。
- 不要把 `DIRECT_URL` 交给应用运行时，或新建第二个 Prisma Client。
- 不要合并学生和管理员 cookie，也不要为 `ADMIN_PASSWORD`、`SESSION_SECRET` 添加 fallback。
