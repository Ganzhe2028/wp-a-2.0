# O-Week v1.1 正式领域 Schema 交接

## 范围

本变更新增正式 `Event` 领域模型、增量 Migration、服务端 ID 工具和领域约束测试。旧 `Person`、`Image`、`LocationCard`、`Favorite`、`SystemSetting` 及其字段保持不变；旧入口继续 fail closed。

Migration 由 Prisma 6.19.3 的 schema-to-schema diff 离线生成，再补充 Prisma Schema 无法表达的两个 PostgreSQL `CHECK`：

- `Day3Bottle.level IS NULL OR level BETWEEN 0 AND 5`；
- `EventAnonymousId.anonymousId` 必须正好 8 个字符。

本阶段未连接或修改 PostgreSQL，未执行生产数据迁移。

## 前滚

1. 备份目标数据库并确认现有 Migration 已全部应用。
2. 使用 `DIRECT_URL` 对目标环境执行正常的 Prisma deploy 流程。
3. 检查新表、enum、外键、唯一约束及两个 `CHECK` 均已建立。
4. 先部署仍保持作品入口 fail closed 的应用版本；不得因表已存在而开放作品访问。
5. 本次发布不得创建 Event、Settings、Group、OIDC User 或任何旧 `Person` 到正式 `User` 的映射、绑定与迁移；不运行 seed 或其他写入流程。

Migration 只创建新 enum、表、索引、外键和约束，不修改旧表或旧数据。

## 恢复

首选恢复方式是回退应用版本并保留新增空表。不要在故障处理中直接 drop 新表或 enum；这可以避免后续已经写入的正式身份、审计和作品数据丢失。若确需物理回滚，必须先导出新表数据，由数据库负责人另行编写并审核独立逆向 Migration。

## 旧 Person 到正式 User

本次发布不执行、也不预置旧 `Person` 到正式 `User` 的映射、绑定或迁移。`Person.code`、`username`、`email` 与名称均不得用作学校不可变 subject；不得据此创建 `User`、关联记录或补偿性写入。

当前不增加 `legacyPersonId` 或任何兼容映射结构，避免在真实映射来源不存在时暗示已经完成身份绑定。未来如确有兼容需求，必须在独立发布中取得经确认的学校 `issuer`、不可变 `externalSubject` 与映射来源，并另行设计、审核和执行迁移方案。

## 未确认产品值

以下内容未写入 Schema 数据、Migration 或默认生成器：

- 六个 Preset 的精确组合；
- Day 1 完整 slot key、比例、必填规则和最终 template version；
- Day 3 完整 bottle key、label 和必填规则；
- Anonymous ID 正式字符表；
- 学校 OIDC issuer、client、scope、claim mapping；
- 生产 Event ID、Event key 和名称；
- 生产 Group 配置；
- 旧 Person 与学校 subject 的真实映射。

所有 `EventSettings` 能力布尔值默认 `false`。Anonymous ID 工具要求调用方显式传入正式字符表，缺失时失败。

## 认证与 API Agent handoff

- 实现 OIDC 后只使用 `(eventId, issuer, externalSubject)` 作为身份唯一键；email 仅为资料字段。
- 不把 `Person.code`、username 或 email hash 写入 `externalSubject`。
- 创建 Submission 时必须同时写入当前 Event，并依赖 `(userId, eventId)` 复合外键阻止跨 Event 关系。
- 所有作品写入在事务内重新读取 `EventSettings` 并做 `version` 乐观锁；缺失或读取失败继续 fail closed。
- `READ_ONLY` 仅由设置、角色和 Submission 状态派生，不能持久化为 `SubmissionStatus`。
- Artwork Public ID 由 `generateArtworkPublicId()` 创建并依赖全局唯一约束处理极低概率碰撞；它只用于寻址，不是访问凭证。
- Anonymous ID 由 `generateAnonymousId()` 在提供正式字符表后创建，并在唯一冲突时按有界重试处理。
- Day 3 Route 必须调用服务端结构和 level 校验，并在事务中检查确认项、活动窗口、template version 与乐观锁。
- `AdminAuditLog.actorUserId = null` 明确表示系统操作；此时 `summary` 必须说明系统来源。审计记录不得随 User 删除而级联删除。
- 不开放 Gallery、Home、Submission API 或现有 Artwork 页面，直到正式授权查询和匿名序列化完成。

## 已知风险

- 完整产品文档仍缺失，模板、瓶子和 Anonymous ID 字符集只能等待确认。
- Migration 已通过静态生成与检查，但尚未在真实 PostgreSQL 执行集成验证。
- `archivedBy` 当前是审计来源字符串，API 层必须采用稳定、非敏感的系统来源或 actor ID 语义并写 Audit Log。
- 新正式模型尚未接入现有 R2、认证或 Route Handler；这是刻意的兼容边界。
