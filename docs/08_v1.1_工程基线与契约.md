## 当前正式流程

学生端：`/login` → `/home` → `/me/day-1`、`/me/day-3` → `/browse` → `/artworks/{publicId}`。

管理员端：`/admin`、`/admin/accounts`、`/admin/audit`。

旧 `/day1`、`/day3`、`/u/{code}` 只能安全跳转；`/nfc/[code]` 与 `/package/[code]` 必须继续 fail closed，不得成为特殊权限入口。

## 当前硬约束

1. 正式身份模型统一使用 `User` 与 `LEARNER | SENIOR | ADMIN` 三角色；本地凭据、OIDC 身份和会话均关联 `User`。
2. 正式作品和图片只使用 `Submission`、`Asset`、`Day1Slot`、`Day3Bottle` 与 `ArtworkPublicId`；不得读取或写入旧 `Person`、`Image`、`Favorite`、`LocationCard`、`SystemSetting`。
3. 设置缺失或读取失败必须 fail closed，不得扩大写权限、浏览权限或公开范围。
4. 所有权限在服务端执行。匿名响应不得包含真实姓名、排序键、组别或可还原身份字段。
5. Day 3 使用 `level: null | 0 | 1 | 2 | 3 | 4 | 5` 与 `isConfirmed` 区分未回答和主动选择 0；空内容不可提交。
6. 所有作品写入必须在事务中按最新正式设置重新授权；提交后的编辑遵循同一权限。
7. 普通账号使用 `ACTIVE | ARCHIVED` 软删除；最后一个 Admin 不得降级或归档。
8. Senior 默认只能浏览自己 Group 内的 Learner；未分组 Senior 必须 fail closed。Gallery 与直接 Artwork URL 必须执行同一服务端权限。
9. 日志不得包含姓名、邮箱、Token、Cookie 或作品内容，只允许 requestId、稳定错误码和不可逆用户摘要。
10. NFC 写卡与展览导出只能使用正式 `/artworks/{publicId}` 链接。

## 接口与工程规则

- 正式 API 统一使用 `/api/v1`；响应使用 `{ data, requestId }` 或 `{ error, requestId }`。
- 先更新 `lib/contracts/**`，再实现 API 和 UI；数据库模型不得直接作为公共 API 类型。
- Node.js 固定 `22.14.0`，npm 固定 `10.9.2`。
- 干净 checkout 必须通过 lint、typecheck、test、生成产物检查、OpenAPI 检查、build 和 harness。
- 生产部署由 `XuChen` 分支触发。部署前必须使用 `https://msoweek.site` 完成学生与管理员完整人工走查。
