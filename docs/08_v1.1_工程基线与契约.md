## 当前正式流程

学生端：`/login` → `/home` → `/me/day-1`、`/me/day-3` → `/browse` → `/artworks/{publicId}`。

管理员端：`/admin`、`/admin/accounts`、`/admin/audit`。

旧 `/day1`、`/day3`、`/u/{code}` 只能安全跳转；`/nfc/[code]` 与 `/package/[code]` 必须继续 fail closed，不得成为特殊权限入口。

## 当前硬约束

1. 正式身份模型统一使用 `User` 与 `LEARNER | SENIOR | ADMIN` 三角色；本地凭据、OIDC 身份和会话均关联 `User`。
2. 正式作品和图片只使用 `Submission`、`Asset`、`Day1Slot`、`Day3Bottle` 与 `ArtworkPublicId`；不得读取或写入旧 `Person`、`Image`、`Favorite`、`LocationCard`、`SystemSetting`。
3. 设置缺失或读取失败必须 fail closed，不得扩大写权限、浏览权限或公开范围。
4. 所有权限在服务端执行。匿名响应不得包含真实姓名、排序键、组别或可还原身份字段。
5. Day 3 使用 `level: null | 0 | 1 | 2 | 3 | 4 | 5` 与 `isConfirmed` 区分未回答和主动选择 0；空内容不可提交。
6. 所有作品写入必须在事务中按最新正式设置重新授权；提交后的编辑遵循同一权限。
7. 普通账号先使用 `ACTIVE | ARCHIVED` 软删除；只有已归档且非受保护系统 Admin 的账号，才可由 Admin 勾选确认后永久清理。ACTIVE 账号不得物理删除；最后一个 Admin 不得降级或归档。
8. Senior 默认只能浏览自己 Group 内的 Learner；未分组 Senior 必须 fail closed。Gallery 与直接 Artwork URL 必须执行同一服务端权限。
9. 日志不得包含姓名、邮箱、Token、Cookie 或作品内容，只允许 requestId、稳定错误码和不可逆用户摘要。
10. NFC 写卡与展览导出只能使用正式 `/artworks/{publicId}` 链接；后台仅导出当前勾选且仍为 ACTIVE 的账号，不得混入归档账号。
11. 受保护初始 Admin 的密码不得写入源码、测试或文档；首次创建和安全迁移必须使用部署环境中的一次性 `PROTECTED_ADMIN_INITIAL_PASSWORD`，成功后移除，并允许通过有审计、会撤销全部会话的单个密码重置进行轮换。
12. R2 Bucket 保持私有。Worker 只允许读取 `processed/` 与 `_derived/processed/`，并必须在返回每个对象前使用签名内部请求让应用按当前会话、活动、提交状态、Group 和可见性设置重新授权；拒绝公共 immutable 缓存。
13. 生产部署使用的 GitHub Actions 必须固定到完整 commit SHA，Vercel CLI 必须显式固定版本；Vercel 与数据库 Secret 只能进入确实使用它们的单个步骤，不得放在 deploy job 全局环境中。

## 接口与工程规则

- 正式 API 统一使用 `/api/v1`；响应使用 `{ data, requestId }` 或 `{ error, requestId }`。
- `/_preview` 仅可在本地 `development` 环境访问，用于 UI 对齐检查；其数据只存在浏览器当前标签页，禁止调用正式 API、数据库、上传或写入操作，生产环境必须返回 404。
- 学生端导航的返回箭头保留 `44px` 触控区域；其字形可作独立视觉校正，需与导航标题的视觉中线对齐。
- Day 1 编辑页与作品展示页共用拼贴网格：除横向主卡外，小卡固定为 `4:3` 横向比例；模板中的图片裁切比例仅用于裁切窗口，不得改变窄屏卡片的列宽或行高。
- Day 1 图片裁切统一以 `100% = 完整图片（contain）` 为缩放基准；新导入图片不得默认截成方形局部，用户可在完整预览上拖动、按键或滑杆放大缩小，编辑页、作品页与分享图必须使用同一裁切结果。
- Day 1 分享图使用固定 15 格的不等尺寸海报拼贴，自动带入当前身份标题、全部作品图片、既有裁切与格子标签；生成前必须并发预载并重试全部 15 张图片，缩略图不可用时回退到已处理原图，任一图片仍未就绪或加载失败时都要中止并明确提示，不得导出缺图海报，也不得退化为对超长编辑页面的直接截图。
- Day 1 上传链路以至少 100 名分散网络用户同时填写为流量基线：每台设备只允许一条图片流水线进入“压缩—直传 R2—安全处理—确认”阶段；处理状态采用带抖动的有限退避查询，不得高频轮询；Vercel 只读取 R2 对象头、受签名保护的 Worker 元数据和媒体授权请求，不得中转完整图片字节。Worker 返回图片前必须实时复核应用会话和作品权限。上传完成后编辑页保留浏览器本地压缩预览，远端缩略图加载超时必须回退到已处理原图，不能无限停留在“图片载入中”；图片编号与裁切值必须写入正式草稿事务，普通保存使用同一幂等键自动重试，离页时使用 `keepalive` 尝试完成最后同步。
- 零外部额度压力测试使用 `npm run test:load:day1`：它只绑定并请求 `127.0.0.1`，以 100 个虚拟用户各上传 15 张 512 KiB 图片，注入可重试故障并核对 100 份最终草稿；该结果验证应用并发、重试和保存模型，不替代真实 Cloudflare、Vercel 与 Neon 链路的少量集成压测。
- Day 3「快乐源泉的小瓶子」采用审定文案 `K歌` 与 `跟朋友打电话`；旧的 `飞歌`、`把酒言欢` 不得继续出现在编辑页、作品页或分享图。
- 先更新 `lib/contracts/**`，再实现 API 和 UI；数据库模型不得直接作为公共 API 类型。
- Node.js 固定 `22.14.0`，npm 固定 `10.9.2`。
- 干净 checkout 必须通过 lint、typecheck、test、生成产物检查、OpenAPI 检查、build 和 harness。
- 生产部署由 `XuChen` 分支触发。部署前必须使用 `https://msoweek.site` 完成学生与管理员完整人工走查。
