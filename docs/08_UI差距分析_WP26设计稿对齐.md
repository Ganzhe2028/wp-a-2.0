# 08 — UI 差距分析：现有代码 vs Figma WP26 设计稿

> 日期：2026-07-31
> Figma 源：`UDxMPWHZeGorGTfgTDVoGr`（WP26），画板 `1058:886` "O-WEEK · WEBSITE PRODUCT UI · Mobile + Admin"
> 代码基线：`feature/oweek-mobile-redesign` 分支（commit 3673cf8 起的活动流改版）

## 0. 总体判断

WP26 设计稿**就是当前代码这次改版（Day 1 / Day 3 活动流）的设计源**。页面结构、核心流程、
文案在代码里已基本实现（登录 → Home → Day1 拼贴 / Day3 小瓶子 → Browse 互解锁 → /u 双 tab
→ NFC 匿名页 → PACKAGE 姓名页 → Admin 后台），所以**这不是一次从零重构，而是对齐 + 补漏 + 清理**。

差距集中在五类：

1. 设计 token（色值、圆角、栅格、字体）未对齐
2. 少量屏幕/状态缺失（裁切屏、上传失败态、会话过期态）
3. 后台开关语义与 Figma 契约不一致（允许编辑、完整资料、跨页导航、mentor scope）
4. 工程契约缺失（version/idempotency、错误码体系）
5. 旧版遗留（死代码、游离页面、过时文档）

另注意：**AGENTS.md 里的设计 token 指向旧 Figma 稿**（`qHFGyH41gsFG4BQMHft8i0` "Welcom👀n"：
#FF530F、75/30/20/12px 圆角、Platform Medium / HYQiHei 80S）。WP26 是新稿，旧 token 全部作废。
WP26 自身的圆角是**小圆角体系**（按钮 4px / pill 14px / 卡片 16px），不是旧稿的大圆角。

## 3. 后台开关语义差距（与 Figma Global Visibility Contract 对照）

代码 admin 现有 6 个开关（admin/page.tsx:29），Figma 契约是另一组语义：

| Figma 契约 | 语义 | 代码现状 |
|---|---|---|
| Day 1 / Day 3 开放 | 未提交用户可进入编辑器 | ✅ `day1Open` / `day3Open` |
| 允许编辑 | **已提交作品可重新编辑** | ❌ 代码把 `browseOpen` 误标为"允许编辑"；提交后 API 永久 409（submissions/route.ts:24,32），无重新编辑能力 |
| show_name=false | 全站匿名符号 ID，API 不返回真实姓名 | 🔶 `showNames` 有，UI 层替换；需验证公共 API 是否泄漏真名 |
| full_profile_visible=false | 详情仅返回身份标题，不返回图片/瓶子 | ❌ `profileComplete` 开关存在于 admin UI 但**全代码无读取点**（死开关） |
| profile_navigation_enabled=false | 隐藏 Browse / 搜索 / 上一位下一位；**NFC 直达仍可打开** | ❌ 无此开关；代码用 `nfcEnabled` 控制 NFC 页开关，语义与 Figma 相反（Figma 语义下 NFC 始终可用） |
| mentor_scope=MY_GROUP_ONLY | Senior Group 结果按服务组过滤，Learner 不受影响 | ❌ 无 `mentorScope` 设置，Browse 不按组别过滤 |

Admin Dashboard 还缺 Figma 里的 "Senior Group 浏览范围 ALL MEMBERS / MY GROUP ONLY" 切换
和"高风险开关"审计说明（代码 Audit Log 页是占位）。

## 4. 工程契约差距（Figma STATE / API / ERROR MAP）

| Figma 契约 | 代码现状 |

## 5. 旧版遗留清单（建议随本次对齐一并处理）

## 6. 动效差距

- 代码仅有：`.ow-enter` 220ms 淡入上移、按钮 180ms hover、瓶子液位 200ms、toggle 滑动
- Figma WP26 有 5 条可点击原型流（Core / Browse Gate / Admin / NFC Anonymous / Find Package），
  但未标注旧稿那种精确转场参数（旧稿的 PUSH↑ 2084ms / spring 1,222,3.7 属于旧设计，不直接沿用）
- 裁决点：页面转场做到什么程度（建议：保持轻量，仅补模态/状态切换过渡，不做重型转场库——stack 冻结）
