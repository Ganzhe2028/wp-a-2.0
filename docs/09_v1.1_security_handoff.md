# O-Week v1.1 P0 安全修复交接

> **历史安全交接记录。** 文中“尚未实现”的模型与路由已被后续正式实现覆盖；当前安全边界以 `docs/08_v1.1_工程基线与契约.md` 为准。

## 本阶段安全边界

- 当前 Schema 没有 `ArtworkPublicId`、`Submission`、`Day3Bottle`、`EventSettings`、正式 `User` 或 `ACTIVE | ARCHIVED` 状态。
- 因此 `/artworks/[publicId]`、`/nfc/[code]`、`/package/[code]`、`/u/[code]`、`/loc/[code]` 统一安全失败，不查询或返回 `Person`、`LocationCard`、`Image`、姓名或资源 URL。
- `showName=false` 的序列化采用字段白名单，只产生安全 `displayTitle`。正式 Anonymous ID 字符表未提供，当前不生成 Anonymous ID。
- 当前基线没有 Gallery/Browse API，也没有 Day 3 保存或提交 Route。Day 3 结构验证器已覆盖空对象、空数组、全 null、全空字符串、未确认和明确 `level: 0`，但正式 Route 必须在新模型落地时接入该服务端验证。
- `browseOpen`、`nfcEnabled`、`profileComplete` 被视为冲突旧设置，不能写入；公开任意设置读取已禁用。
- 常规账号 `DELETE` 明确拒绝，不执行 Prisma 物理删除。

## Schema/Migration Agent 后续工作

1. 新建正式 `ArtworkPublicId` 与 `Submission` 后，让统一可见性函数只按 Public ID、当前用户角色、作品状态和正式 EventSettings 做决定；不要恢复 code/context/query 参数旁路。
2. 新建 `EventAnonymousId` 后替换匿名占位标题。正式符号表必须来自缺失的 v1.1 产品原文，禁止推断。
3. 新建 `Day3Bottle` 和正式 `isConfirmed` 字段后，在事务内执行结构完整性、确认项、活动窗口和版本冲突校验。瓶子 key/必填规则等待产品原文。
4. 新建 `EventSettings` 后用类型化读取替换 `SystemSetting`；缺失、解析错误和数据库异常继续 fail closed。
5. 新建正式数据库 `User`、角色和 `ACTIVE | ARCHIVED` 后实现归档，并在同一事务保护最后一个 `ADMIN`。当前 Admin 仍是环境变量共享口令，无法证明最后一个 Admin 保护。
6. 模型落地前不要重新开放任何旧作品入口。
